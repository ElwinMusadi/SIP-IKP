# Identity and Access Threat Model

## 1. Scope and Purpose

This document provides a systematic threat model for the identity, authentication, session management, and access control boundaries of the **Sistem Informasi Pelaporan Insiden Keselamatan Pasien (IKP) IBS RSUD Prof. Dr. W. Z. Johannes Kupang**.

This threat model is a **technical architecture evaluation**, not a formal security certification or compliance guarantee. It serves as the baseline for evaluating candidate mitigations, defining test matrices, and guiding stakeholder decisions prior to production implementation.

## 2. Target Environment Context

- **Operating Context:** Central Surgical Installation (IBS) operating theaters, induction rooms, PACU, and PMKP quality committee offices.
- **Physical Environment:** Shared hospital workstations used sequentially by nurses, surgeons, and anesthesiologists during shifts.
- **Network Environment:** Hospital LAN and edge-routed cloud infrastructure via Cloudflare Pages and D1.
- **Data Sensitivity:** Confidential clinical incident reports, staff findings, medical chronology, patient identifiers, and digital approval attribution.

## 3. Threat Assessment Matrix

| ID        | Threat Category                                      | Target Asset                                             | Attack Surface                                                     | Impact                                                                                  | Candidate Mitigation                                                                                                                                                                          | Status      |
| --------- | ---------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| **TH-01** | Credential Theft (Transit / Storage)                 | User passwords, password hashes                          | Login API transport, D1 database storage, backup snapshots         | Account takeover across clinical and administrative roles                               | Mandate TLS 1.3 / HTTPS; one-way adaptive password hashing (Argon2id or PBKDF2 >=600k); random salt per user; optional pepper in Cloudflare Secrets; zero plaintext storage                   | PROVISIONAL |
| **TH-02** | Session Theft (Network / Token Sniffing)             | Session cookie / session token                           | HTTP traffic, unencrypted proxies, browser inspection              | Attacker impersonates legitimate clinical user                                          | Host-only `__Host-` cookie prefix, `Secure` flag, `HttpOnly` flag, TLS termination at Cloudflare edge                                                                                         | PROVISIONAL |
| **TH-03** | Session Fixation                                     | Session token                                            | Pre-authentication cookie accepted post-login                      | Attacker pre-sets a known session ID and hijacks authenticated session                  | Regenerate and issue fresh random session ID upon successful login; destroy pre-auth session                                                                                                  | PROVISIONAL |
| **TH-04** | Session Replay                                       | Session cookie / token digest                            | Stolen cookie replayed after legitimate user departs terminal      | Unauthorized access to patient reports on shared terminals                              | 15-minute server-side sliding idle timeout; absolute session lifetime ceiling; immediate server-side revocation on logout; optional client IP / User-Agent anomaly binding                    | PROVISIONAL |
| **TH-05** | Cross-Site Request Forgery (CSRF)                    | State-changing API commands (submit, grade, revise)      | Cross-origin requests via browser cookie auto-attach               | Attacker tricks logged-in nurse/doctor into submitting or mutating incident data        | `SameSite=Strict` cookie attribute; strict `Origin` and `Fetch Metadata` validation; synchronizer anti-CSRF token in custom `X-CSRF-Token` header for all unsafe methods                      | PROVISIONAL |
| **TH-06** | Cross-Site Scripting (XSS) Impact on Auth            | Authentication tokens, session state                     | Injected scripts via unescaped patient name, chronology, or notes  | Exfiltration of session tokens if accessible via DOM                                    | `HttpOnly` cookie prevents JavaScript access to session tokens; zero auth tokens in `localStorage` or `sessionStorage`; strict CSP (`script-src 'self'`); automatic framework output encoding | PROVISIONAL |
| **TH-07** | Brute Force Attacks                                  | User passwords                                           | `POST /auth/login` endpoint                                        | Offline and online password guessing targeting staff accounts                           | Progressive delay (exponential backoff) on failed attempts; temporary account lockout after 10 failures; Cloudflare edge rate limiting per IP and per account                                 | PROVISIONAL |
| **TH-08** | Credential Stuffing                                  | User accounts across hospital                            | `POST /auth/login` endpoint                                        | Mass compromise of recycled staff passwords from external breaches                      | Prohibit common default passwords; screen against common password blacklist; Cloudflare WAF bot mitigation and IP rate limiting; optional MFA for privileged accounts                         | PROVISIONAL |
| **TH-09** | Password Reset Abuse                                 | Password reset tokens, user credentials                  | `POST /auth/password/reset/*` endpoints                            | Attacker triggers unauthorized reset or brute-forces reset token                        | Cryptographically random, single-use reset token; stored only as SHA-256 digest in D1; 15-minute token TTL; rate limit reset requests; consume token immediately upon use                     | PROVISIONAL |
| **TH-10** | Account Enumeration                                  | Username / NIP presence in hospital directory            | Login, reset, and password recovery API responses                  | Attacker discovers valid staff NIPs and email addresses                                 | Strictly uniform response messages (`"Kredensial tidak valid"`); constant-time comparison on password checks; uniform responses on password reset regardless of user existence                | PROVISIONAL |
| **TH-11** | Privilege Escalation (Vertical Authorization)        | User roles (`ADMINISTRATOR`, `KOMITE_PMKP`)              | Privilege-bearing API endpoints (master data, regrade, completion) | `TENAGA_KESEHATAN` performs administrative or committee-level approvals                 | Enforce server-side role verification in Pages Functions; reject client-supplied roles; prohibit self-assignment of roles in API                                                              | PROVISIONAL |
| **TH-12** | Horizontal Authorization Failure (IDOR / BOLA)       | Incident reports, investigation drafts                   | `GET /incidents/{id}`, `PATCH /incidents/{id}`                     | Clinician reads or tampers with another clinician's report across identical role        | Server verifies `created_by_user_id == current_user_id` for draft access; enforce explicit ownership query predicate in D1                                                                    | PROVISIONAL |
| **TH-13** | Vertical Authorization Failure (Cross-Role Mutation) | Risk grading, simple investigation approval              | Workflow transition endpoints                                      | Reporter grades their own incident or approves an investigation                         | State transition handlers validate actor role against transition matrix (`WORKFLOW-STATE-MACHINE.md`); client UI is never trusted                                                             | PROVISIONAL |
| **TH-14** | Unit-Scope Bypass                                    | Incident reports belonging to other wards/units          | Incident listing and detail query endpoints                        | IBS staff access non-IBS incidents, or non-IBS staff inspect surgical incidents         | Query predicates mandate `owning_unit_id == current_user_unit_id`; prohibit free-text unit name matching; PMKP access requires explicit scope grant                                           | PROVISIONAL |
| **TH-15** | Session Revocation Failure                           | Active session records in D1                             | Terminated employee, changed password, or logged out session       | Stale session continues executing commands after administrative action                  | Server validates D1 session status (`revoked_at IS NULL`) and user status (`status = 'ACTIVE'`) on every non-cached request; bulk revoke on password change                                   | PROVISIONAL |
| **TH-16** | Stale Authorization State                            | Cached role/permission assignments                       | Long-lived session retaining old permissions after role change     | User whose role was demoted continues performing privileged approvals                   | Check current user status and active role assignments in D1 for every permission-sensitive transaction; reject stale session claims                                                           | PROVISIONAL |
| **TH-17** | Audit Attribution Failure                            | Domain audit trail (`audit_records`)                     | Audit logging pipeline                                             | Inability to prove who performed a medical approval or investigation                    | Capture immutable attribution snapshot (Name, NIP, Role, Unit, Timestamp, Request ID) atomically in the same D1 transaction as domain mutation; reject unauthenticated commands               | PROVISIONAL |
| **TH-18** | Sensitive Data Leakage Through Logs                  | Passwords, tokens, PHI (patient name, MR, narrative)     | Application logs, Cloudflare console, observability traces         | Accidental disclosure of confidential health information to operations personnel        | Centralized recursive redaction utility (`functions/_shared/log-redaction.ts`); log only route templates and error codes; never log request/response bodies by default                        | PROVISIONAL |
| **TH-19** | Insecure Browser Storage                             | Session tokens, patient draft narrative, medical records | Browser `localStorage`, `sessionStorage`, `IndexedDB`              | Data left on shared terminal readable by next user of PC                                | Zero credentials or tokens in browser web storage; all drafts stored server-side under authenticated session; form state cleared on logout/idle timeout                                       | PROVISIONAL |
| **TH-20** | Administrative Account Abuse                         | System user accounts, master data, audit logs            | Admin configuration and user management APIs                       | Malicious or compromised admin alters historical incident records or hides audit trails | Disallow manual `UPDATE` or `DELETE` on audit tables; administrators receive no clinical viewing/editing permissions by default; separate technical administration from clinical governance   | PROVISIONAL |

## 4. Threat Summary & Implementation Readiness

1. **Shared Terminal Exposure:** The primary physical threat vector is clinicians leaving shared operating theater terminals unattended. The candidate mitigations (**15-minute server-authoritative idle timeout**, **`HttpOnly` host-only cookies**, **zero client-side storage of PHI**) directly address this threat.
2. **Edge Serverless Security:** Cloudflare Pages Functions isolates and D1 require defense-in-depth: rate limiting, edge security headers, CSRF tokens on mutating calls, and server-side authorization enforcement.
3. **No Certification Claimed:** This model identifies technical mitigations. Formal hospital privacy certification requires administrative governance, staff training, physical security policies, and legal oversight outside the scope of this repository.
